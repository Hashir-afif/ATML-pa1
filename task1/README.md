# Task 1: Inductive Biases and Feature Representations

## Purpose

This task compares a CNN (ResNet-50), a Vision Transformer (ViT-B/16) and CLIP (ViT-B-32) under
controlled image interventions. The goal is to find out which visual cues (colour, shape vs.
texture, spatial arrangement) drive their predictions, and whether their frozen representations move
when those cues change.

## Dataset

**STL-10** (recommended by the manual): 10 classes, 96×96 images. Every image is upsampled
bicubically to the common 224×224 intervention resolution.

- Head training: stratified 80/20 split of the **official training partition** (5000 images), seed 6304.
- Evaluation: a **class-balanced 500-image subset of the official test split** (50 per class), seed 6304.
  The selected image IDs are saved in `results/subset/subset_ids.json`.

STL-10 is downloaded automatically to `task1/data/`, which git ignores.

## Models (all frozen)

| Backbone | Weights | Representation |
|---|---|---|
| torchvision ResNet-50 | `ResNet50_Weights.IMAGENET1K_V2` | global-average-pooled feature (2048-d) |
| torchvision ViT-B/16 | `ViT_B_16_Weights.IMAGENET1K_V1` | final class token (768-d) |
| OpenCLIP ViT-B-32 | `pretrained='openai'` | L2-normalised image embedding (512-d) |

Each backbone gets one linear head: AdamW, lr 1e-3, weight decay 1e-4, at most 50 epochs, early
stopping after 5 epochs without a validation-accuracy improvement, and seed 6304. CLIP is also
evaluated zero-shot with the manual's fixed prompt, `a photo of a {class}.` The trailing period is
kept as the manual writes it. There is no prompt search.

## Pipeline (run in order)

| # | Notebook | Manual step | Main outputs |
|---|---|---|---|
| 00 | `00_setup_and_design.ipynb` | setup, design choices + hypotheses | `results/design_choices.json` |

| 03 | `03_make_cue_conflicts.ipynb` | AdaIN cue conflicts + model-free rejection rule | `cache/sets/cue_conflict.pt`, `results/cue_conflicts/`, `results/tables/cue_conflict_acceptance.csv` |
| 04 | `04_backbones_and_heads.ipynb` | frozen features, linear heads, CLIP zero-shot | `cache/features/`, `cache/heads/`, `cache/outputs/task1_outputs.pt` |
| 05 | `05_evaluate_bias.ipynb` | Steps 1–5 (clean, colour, shape/texture, translation, patches) | `results/tables/task1_*`, `results/figures/task1_*` |
| 06 | `06_representation_analysis.ipynb` | Step 6 (cosine stability, prediction vs representation, t-SNE) | `results/tables/task1_*`, `results/figures/task1_*` |

Notebooks 01–03 fix every evaluation image **before any recognition model is loaded**. Every model
therefore receives exactly the same pixels, and cue-conflict retention cannot depend on model
predictions.

(On Linux/macOS use `../.venv/bin/jupyter`.) Smoke test: set `TASK1_SMOKE=1` before running 04.
This trains the heads on 200 images for 2 epochs. Notebook 07 refuses to export smoke outputs.

## Configuration

`configs/task1_config.json` holds every setting: the seed, subset size, head hyperparameters, CLIP
prompt, hue shift (0.5 = 180°), translation displacements and directions, the 4×4 patch grid,
cue-conflict pairs, style strength and rejection thresholds, and the t-SNE settings.

## Outputs

- `task1/results/tables/`, `task1/results/figures/` hold the working copies (small, git-tracked).
- `results/task1/` (top level) holds all tables plus the consolidated `results.json`.
- `figures/task1/` (top level) holds all figures as PNG and PDF.
- `task1/cache/` and `task1/data/` hold large tensors and the raw dataset (git-ignored, regenerated by the notebooks).

## Mapping to the manual's suggested structure

The manual *suggests* separate `.py` modules. This project uses notebooks instead. Each notebook
does one step, and image generation stays separate from evaluation, which is the requirement the
manual states:

```
01_make_subset.ipynb        ->  data/make_subset.py
02_make_transforms.ipynb    ->  data/transforms.py
03_make_cue_conflicts.ipynb ->  data/make_cue_conflicts.py
04_backbones_and_heads      ->  models/backbones.py
05_evaluate_bias            ->  analysis/evaluate_bias.py
06_representation_analysis  ->  analysis/feature_similarity.py + analysis/representation.py
00..07 in order             ->  scripts/run_task1.py
```

## External code

- **AdaIN** (`03_make_cue_conflicts.ipynb`): the network definition (VGG-19 encoder up to `relu4_1`
  and the mirrored decoder) is a compact rewrite of <https://github.com/naoto0804/pytorch-AdaIN>
  (Huang & Belongie, 2017). The pretrained `vgg_normalised.pth` and `decoder.pth` weights are
  downloaded from that repository's release. Modifications: batched uint8 I/O at 224×224 and
  interpolation of the output back to 224 when needed.
- Pretrained backbones come from torchvision and OpenCLIP. Weights are used unchanged.

## Reproducibility

Seed 6304 is used for the subset, the head split, the patch permutations (`6304 + image index`),
cue-conflict candidate sampling, head initialisation and shuffling, and t-SNE. Subset IDs, split
indices, patch permutations and cue-conflict metadata (including rejection reasons) are all saved.
